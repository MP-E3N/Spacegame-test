## Schnittstelle (Vorschlag der Projektleitung — in der Frühwarnung schärfen)
Schiff lokal wie immer: Meter, +Z Bug, +X Backbord, +Y oben.

**Modul** (`src/sim/werft/module.js`, ohne three, reine Daten):
```js
{
  id: 'rumpf_m_lang', name: 'Rumpfsegment lang', art: 'rumpf' | 'bug' | 'heck' | 'kommando' | 'anbau' | 'turm',
  teile: [{ ab: [{ z, w, h, x?, y? }], fase }],   // Lofts in Modul-Koordinaten, Format wie TEILE (halbe Maße)
  kisten?: [{ b, h, t, x, y, z }],                  // feste Zusatzklötze (Grafik + Kugeln), optional
  andock: [{ id: 'vorn', p: [x, y, z], n: [0, 0, 1], groesse: 'M', art: 'rumpf' }],  // n = Achsrichtung nach außen
  kugeln: [{ x, y, z, r }],                         // Kollision/Überschneidung (Modul-Koordinaten)
  turm?: { typ: 'flak' | 'schwer', s },             // nur art 'turm': Turm sitzt im Ursprung, +Y vom Rumpf weg
  werte: { masse, panzer?, schub?, besatzung? },    // Anzeige im Editor (Tonnen, frei gewählte Einheiten)
}
```
- Andockpunkt: Punkt `p` auf der Andockfläche, Richtung `n` ∈ {±X, ±Y, ±Z} zeigt aus dem Modul hinaus.
- Größen: `S` (Anbau/Turm, Fläche ~5 m), `M` (Rumpf ~10 m Halbbreite), `L` (Rumpf ~18 m). Passt nur gleiche Größe und
  gleiche `art`-Familie (`rumpf` an `rumpf`, `anbau` an `anbau`).

**Entwurf** (gespeichert als `konfig/schiffe/<name>.json`):
```js
{ name, kennung, version: 1,
  teile: [{ nr: 0, modul: 'kommando_m' },                                  // Wurzel im Ursprung, ohne Drehung
          { nr: 1, modul: 'rumpf_m_lang', an: { nr: 0, punkt: 'hinten' }, punkt: 'vorn', dreh: 0 }] }
```
- Ein Teil hängt an genau einem Elternteil (Baum). `dreh` ∈ 0..3 = Vierteldrehungen um die Andockachse.
- Andocken: Kindpunkt liegt auf dem Elternpunkt, Kind-`n` = −Eltern-`n`, danach `dreh`. Kindteile werden beim Löschen
  mitgelöscht. Rotationen nur aus 90°-Schritten → Matrizen ganzzahlig (keine Rundungsdrift).

**Zusammenbau** (`src/sim/werft/zusammenbau.js`): `baue(entwurf, katalog)` →
`{ teile: [{ nr, modul, lage: { m: [3×3 ganzzahlig], t: [x, y, z] } }], freiePunkte, kugeln, tuerme, werte, laenge, meldungen }`
- `meldungen`: `{ stufe: 'fehler' | 'warnung', text, nr? }` — Fehler: unbekanntes Modul, Punkt belegt, Größe/Art passt
  nicht, Überschneidung (Kugeln zweier nicht benachbarter Teile ragen > 1 m ineinander), kein Kommando, kein Heck/Triebwerk.
  Warnung: offene Rumpf-Andockfläche (Loch), kein Turm, mehr als 1 Kommando.
- Ein Entwurf mit Fehlern darf gespeichert werden (Starfield-Lehre), er ist nur „nicht flugfähig“.

## Frühwarnung
- **Prüfer:** (1) Drehung aus „Kind-n = −Eltern-n“ ist bei 180° nicht eindeutig → Bezugsachse u je Punkt. (2) Baum-Fehler
  (Zyklus, doppelte/fehlende nr, mehrere Wurzeln, Liste ungeordnet) als Meldung, nie Absturz; Rückgängig über ganze
  Schnappschüsse. (3) Widerspruch „mehrere Teile je Punkt“ vs. „Punkt belegt“; Ring-Schluss = deckungsgleiche Punkte gelten
  als belegt. (4) Kugeln direkter Nachbarn überlappen immer → Nachbarn ausnehmen, Schwelle gegen Beispielschiffe messen.
  (5) Ablage verallgemeinern (Fabrik mit exportiertem Handler, testbar), nicht kopieren. (6) Version: höhere → Meldung,
  `migriere()`-Kette, `ersetzt` im Katalog. (7) Importprüfung in tests/schiffe.mjs deckt `src/sim/werft/` nicht ab.
- **Schiffbauer:** (1) Lofts je Modul entlang Z reichen; `fusspunkt`/`rumpfSperre`/`turmDaten` nur im Modul rechnen, S-Turmpunkte
  nur ±Y. (2) Eltern-Modul trägt an jedem S-Turmpunkt eine flache Lafettenplatte → Turm immer auf y = 0, Schürze 0,1.
  (3) `aufbauten()`: Zufall je Modul aus Hash der Id, alle S-Punkte gesperrt, Rand 1,5 m vor Andockflächen (neue Option in
  bauteile.js, Standard aus → Bollwerk/Ambos bitgleich). (4) Normquerschnitte M {w 10, h 8, fase 0,3}, L {w 18, h 13, fase 0,3}.
  (5) w ≠ h → Rumpfflächen nur dreh 0/2. (6) Spiegelpaare `_bb`/`_sb` statt Spiegelmatrix. (7) `art` gehört zum Punkt.
  (8) Überschneidung mit Hüllquadern statt Kugeln. (9) Draw-Calls: ganzes Schiff je Material zu einem Netz zusammenfügen,
  Türme einschmelzen; Matrix je Teil nur für Geist/Auswahl.

## Entscheidungen
- **E1 Lage:** Jeder Andockpunkt hat `p` (0,5-m-Raster), `n` (Achse nach außen) und `u` (Bezugsachse ⟂ n; Rumpfflächen
  u = +Y, Punkte mit n = ±Y: u = +Z). Andocken: Kind-Drehung R so, dass R·n_K = −n_E und R·u_K = u_E, danach `dreh`
  Vierteldrehungen um n_E (rechtsdrehend). det = +1 immer. t = t_E + M_E·p_E − M_K·p_K (Welt). `m` zeilenweise
  `[[r00, r01, r02], [r10, …], …]`, ganzzahlig.
- **E2 Punkt-Art + Größe:** passt nur gleiche Größe **und** gleiche Punkt-`art` (`rumpf` | `anbau` | `turm`). Punkt hat
  `dreh: [erlaubte Werte]` (Rumpf [0, 2], S [0, 1, 2, 3]).
- **E3 Ein Teil je Punkt.** Zwei deckungsgleiche Punkte (Lage < 1 mm, n entgegen, passend) fremder Teile gelten als
  verbunden (Ring-Schluss), nicht als offen.
- **E4 Spiegelpaare** `_bb`/`_sb` erzeugt der Katalog aus gespiegelten Daten (keine Spiegelmatrix).
- **E5 Überschneidung:** Hüllquader je Loft/Kiste (in Weltlage achsparallel, exakt), um 0,5 m geschrumpft; Paare, die direkt
  oder per Ring-Schluss verbunden sind, ausgenommen. Schwelle so, dass das Beispielschiff 0 Treffer hat. `kugeln` bleiben im
  Modul (Kollision später).
- **E6 Meldungen** `{ code, stufe: 'fehler' | 'warnung', text, nr? }`, Codes fest: `modul_unbekannt`, `punkt_unbekannt`,
  `punkt_belegt`, `passt_nicht`, `dreh_verboten`, `eltern_fehlt`, `zyklus`, `wurzel`, `nr_doppelt`, `ueberschneidung`,
  `kein_kommando`, `kein_heck`, `version` (Fehler) · `offen_rumpf`, `kein_turm`, `mehrere_kommando` (Warnung).
- **E7 Exporte:** `src/sim/werft/module.js` → `MODULE` (Liste), `KATALOG` (id → Modul), `NORM`. `src/sim/werft/beispiel.js`
  → `BEISPIEL` (Entwurf ~20 Module, Testvorlage + Editor-Start). `src/sim/werft/zusammenbau.js` → `baue(entwurf, katalog)`,
  `LAGEN` (24), `andockLage(...)`, `kandidaten(entwurf, katalog, modulId)` (alle freien passenden Punkte mit Lage, für den
  Geist), `migriere(entwurf)`. Grafik `src/grafik/schiff/module.js` → `modulGeometrie(id)` (zwischengespeichert, je Material)
  und `schiffNetz(teile)` (Liste {modul, lage} → THREE.Group, je Material ein Netz, Türme eingeschmolzen).
- **E8 Ablage:** `server/ablage.js` → `ablage({ pfad, ordner })` (Fabrik, Handler exportiert); vite.config nutzt sie für
  `/api/flak-konfig` (unverändert) und `/api/schiffe` → `konfig/schiffe/`. Laden überliest fremde Felder.
- **E9 Buchse/Stecker** (nach Prüfer-Befund Teil 1: Rumpf ließ sich mit seinem Turmpunkt kopfüber auf einen Turmpunkt
  setzen): bei Punkt-`art` ≠ `rumpf` passt nur Buchse (Elternteil, Standard) an Stecker (Kind, `stecker: true`).
  Außerdem: Startteil = kleinste nr, doppelte nr deterministisch (Ergebnis unabhängig von der Listenreihenfolge).
- **Besitz:** Schiffbauer = module.js, beispiel.js, grafik/schiff/module.js, bauteile.js (Rand-Option). Projektleitung =
  zusammenbau.js, server/ablage.js, vite.config.js, werft.html, src/werft/*, Menü. Prüfer = tests/werft.mjs, tests/schiffe.mjs
  (Importprüfung + werft), package.json test.
